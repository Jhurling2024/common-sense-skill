# Generalized failure patterns (sanitized)

These patterns summarize recurring challenges from the originator's accessible project conversations. They are **illustrative lessons**, not proof of comprehensive archive coverage and not transcripts. Internal paths, credentials and private IDs are intentionally omitted.

1. **Missed native workflow** — AI recommended complex bridges repeatedly without first assessing whether the official desktop experience or a supported native connector could reduce friction. Fix: mandatory native-capability discovery; explicitly verify plan/OS support before claiming it works.
2. **ACK mistaken for execution** — a message listener accepted a GitHub comment, yet the authenticated local execution backend was unreachable. Fix: report delivery, intake, coordinator receipt, backend health, task output as distinct checks.
3. **Successful artifact, failed deployment** — multiple web ZIPs passed integrity checks while cloud browser layouts remained wrong. Fix: test the same preview URL, width, assets and cache the user will deploy.
4. **Unwanted features reappeared** — translation UI, chatbots or lead forms returned despite explicit removal requests. Fix: treat negative requirements as release tests and do a full-site search.
5. **Paid service suggested despite zero-spend** — browser automations and SaaS recommendations were made without first checking whether local or free alternatives would satisfy the requirement. Fix: pricing and credit check before recommending any external service.
6. **Green suite, untested failure path** — passing tests did not cover critical job/handler modules. Fix: map regression coverage to real failure conditions; independent negative tests required for readiness.
7. **Autostart not durable** — successful one-off restart/health report obscured missing post-reboot startup and security maintenance interference. Fix: reboot persistence and real environmental interference are part of the acceptance test.
8. **Too many agents** — overlapping watchers and orchestration layers increased failure modes. Fix: use one authorized coordinator, existing maintenance owner, deduplicated queues and minimal new infrastructure.
9. **Software license assumption** — visible source or high GitHub star counts were conflated with permissible commercial redistribution. Fix: check exact repository, model weights and transitive components before proposing installation.
10. **Unverified "live" assertion** — local generated files, online dashboard state and an unpublished deployment were conflated. Fix: separate produced, uploaded, deployed and end-user verified.

Whenever one repeats: identify the exact broken inference, design a new behavioral eval case, and ask the owner to approve the updated skill version before broad activation.
